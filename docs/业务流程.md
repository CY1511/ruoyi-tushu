# 若依书铺 - 业务流程

> 状态码口径与 `IdleGoods` / `IdleOrderStatus` 保持一致：
> 商品 `goodsStatus` 0待审核 1上架 2已预订 3已售出 4已下架，订单 `orderStatus` 0待确认 1交易中 2已完成 3已取消。
> 代码里的权威定义见 `ruoyi-system` 的 `IdleGoods`（状态常量）与 `IdleOrderStatus`（流转表），本文只讲流程。


## 一、系统角色定义
| 角色 | 说明 | 核心职责 |
| --- | --- | --- |
| **买家** | 购买商品的用户 | 下单、确认收货、取消订单、收藏商品、聊天沟通 |
| **卖家** | 发布商品的用户 | 发布商品、确认订单、与买家沟通 |
| **管理员** | 平台运营人员 | 审核商品、管理用户、处理纠纷 |
| **游客** | 未登录用户 | 浏览商品、查看详情 |

### 2.2 商品状态详细说明
| 状态码 | 状态名称 | 触发条件 | 前台是否可见 | 可操作 |
| --- | --- | --- | --- | --- |
| 0 | 待审核 | 用户发布商品 | ❌ | 用户修改、管理员审核 |
| 1 | 上架 | 审核通过 | ✅ | 用户下架、买家下单、收藏 |
| 2 | 已预订 | 买家下单成功 | ❌ | 卖家确认、买家取消 |
| 3 | 已售出 | 交易完成 | ❌ | 仅查看 |
| 4 | 已下架 | 审核驳回/卖家下架 | ❌ | 用户修改后重新提交 |


### 2.3 商品发布流程（详细）
**步骤1：用户填写商品信息**

```plain
├── 必填：分类、商品名称、售价
├── 选填：原价、成色、描述、联系电话、交易地点、封面图片
└── 系统自动填充：发布人ID（当前用户）
```

**步骤2：提交发布**

```plain
├── 调用接口：POST /system/goods
├── 系统设置：
│   ├── auditStatus = "0"（待审核）
│   ├── goodsStatus = "0"（待审核）
│   └── createTime = 当前时间
└── 响应：返回商品ID
```

**步骤3：管理员审核**

```plain
├── 调用接口：PUT /system/goods/audio
├── 审核通过：
│   ├── auditStatus → "1"（通过）
│   ├── goodsStatus → "1"（上架）
│   └── 商品在前台可见
└── 审核驳回：
    ├── auditStatus → "2"（驳回）
    ├── goodsStatus → "4"（已下架）
    ├── 记录审核意见
    └── 用户可修改后重新提交
```

### 2.4 审核状态详细说明
| 状态码 | 状态名称 | 触发条件 | 商品状态变化 | 用户操作 |
| --- | --- | --- | --- | --- |
| 0 | 待审核 | 用户发布 | 保持0 | 修改、等待审核 |
| 1 | 通过 | 管理员审核通过 | 0→1（上架） | 等待买家下单 |
| 2 | 驳回 | 管理员审核驳回 | 0→4（下架） | 修改后重新提交 |

### 3.2 订单状态详细说明
| 状态码 | 状态名称 | 说明 | 可操作角色 | 后续操作 |
| --- | --- | --- | --- | --- |
| 0 | 待确认 | 买家刚下单，等待卖家确认 | 卖家 | 卖家确认（同意/拒绝） |
| 1 | 交易中 | 卖家已同意，交易进行中 | 买家 | 买家完成或取消 |
| 2 | 已完成 | 买家确认收货，交易结束 | - | 仅查看 |
| 3 | 已取消 | 订单已取消 | - | 仅查看 |


### 3.3 下单流程（详细）
**步骤1：买家选择商品**

```plain
├── 前置条件：商品状态必须为 "1"（上架）
├── 查看商品详情
└── 点击"立即购买"
```

**步骤2：填写订单信息**

```plain
├── 商品ID：自动带入
├── 成交价格：自动带入商品售价（可协商后修改）
├── 备注：可填写特殊要求
└── 系统自动填充：买家ID（当前用户）
```

**步骤3：提交订单**

```plain
├── 调用接口：POST /system/order
├── 系统自动填充：
│   ├── orderNo：ORD + 时间戳 + 4位随机码
│   ├── buyerId：当前登录用户
│   ├── sellerId：商品发布人ID
│   ├── orderStatus："0"（待确认）
│   └── createTime：当前时间
├── 商品状态变化：
│   └── goodsStatus："1"（上架）→ "2"（已预订）
└── 响应：返回订单信息（含订单号）
```

### 3.4 卖家确认流程（详细）
**前置条件：**

```plain
├── 订单状态必须为 "0"（待确认）
└── 当前用户必须是订单的卖家
```

**【同意】**

```plain
├── 调用接口：PUT /system/order/confirm
├── 请求参数：{ "orderId": 1001, "orderStatus": "1" }
├── 订单变化：orderStatus "0" → "1"（交易中）
├── 商品变化：goodsStatus 保持 "2"（已预订）
└── 通知买家：卖家已接单
```

**【拒绝】**

```plain
├── 调用接口：PUT /system/order/confirm
├── 请求参数：{ "orderId": 1001, "orderStatus": "3", "cancelReason": "..." }
├── 订单变化：orderStatus "0" → "3"（已取消）
├── 商品变化：goodsStatus "2" → "1"（上架，恢复可售）
├── 记录取消原因
└── 通知买家：卖家已拒绝
```

### 3.5 买家操作流程（详细）
**前置条件：**

```plain
├── 订单状态必须为 "1"（交易中）
└── 当前用户必须是订单的买家
```

**【完成订单】**

```plain
├── 调用接口：PUT /system/order/complete
├── 请求参数：{ "orderId": 1001 }
├── 订单变化：orderStatus "1" → "2"（已完成）
├── 商品变化：goodsStatus "2" → "3"（已售出）
├── 记录完成时间：finishTime = 当前时间
└── 交易结束
```

**【取消订单】**

```plain
├── 调用接口：PUT /system/order/cancel
├── 请求参数：{ "orderId": 1001, "cancelReason": "..." }
├── 订单变化：orderStatus "1" → "3"（已取消）
├── 商品变化：goodsStatus "2" → "1"（上架，恢复可售）
├── 取消原因必填
└── 交易终止
```



## 四、商品收藏流程
### 4.1 收藏流程图
```plain
┌─────────────────────────────────────────────────────────────────────────────────┐
│                              商品收藏流程                                      │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  用户浏览商品                                                                    │
│       │                                                                         │
│       ▼                                                                         │

│       │                                                                         │
│       ▼                                                                         │
│  调用接口：POST /system/collect                                                  │
│       │                                                                         │
│       ▼                                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐            │
│  │  检查是否已收藏（userId + goodsId）                             │            │
│  │    ├── 已收藏 → 返回"已收藏"提示                               │            │
│  │    └── 未收藏 → 插入收藏记录                                   │            │
│  └─────────────────────────────────────────────────────────────────┘            │
│       │                                                                         │
│       ▼                                                                         │

│                                                                                 │

│                                                                                 │
│  用户再次点击"已收藏"按钮                                                        │
│       │                                                                         │
│       ▼                                                                         │
│  调用接口：DELETE /system/collect/goods/{goodsId}                               │
│       │                                                                         │
│       ▼                                                                         │
│  删除收藏记录，更新商品收藏数（collectCount - 1）                               │
│       │                                                                         │
│       ▼                                                                         │
│  按钮变为"收藏"状态                                                              │
│                                                                                 │

```

### 4.2 收藏状态说明
| 状态 | 说明 | 按钮显示 | 接口 |
| --- | --- | --- | --- |
| 未收藏 | 用户未收藏该商品 | "收藏" | POST /system/collect |
| 已收藏 | 用户已收藏该商品 | "已收藏" | DELETE /system/collect/goods/{goodsId} |


### 4.3 收藏业务规则
1. 一个用户对同一个商品只能收藏一次（唯一约束：`user_id` + `goods_id`）
2. 收藏数实时更新，用于商品详情页展示热度
3. 取消收藏后商品收藏数减1
4. 商品下架或删除后，关联的收藏记录可保留或删除（根据业务需求）

### 5.2 WebSocket 消息类型汇总
| 消息类型 | 方向 | 触发场景 | 说明 |
| --- | --- | --- | --- |
| `message` | 服务端 → 客户端 | 收到新消息 | 普通聊天消息，含消息内容、发送者信息 |
| `system` | 服务端 → 客户端 | 连接成功/错误 | 系统通知 |
| `read` | 客户端 → 服务端 | 用户查看消息 | 已读回执请求 |
| `read_receipt` | 服务端 → 客户端 | 消息被阅读 | 已读回执确认 |
| `ping` | 客户端 → 服务端 | 保持连接 | 心跳检测 |
| `pong` | 服务端 → 客户端 | 心跳响应 | 心跳响应确认 |


### 5.3 聊天室会话状态
| 状态 | 值 | 说明 |
| --- | --- | --- |
| 正常 | 0 | 会话正常，可收发消息 |
| 已关闭 | 1 | 会话关闭，不可收发消息 |


### 5.4 未读消息流程详解
```plain
接收方收到新消息（不在当前会话中）
        │
        ▼
未读消息数 +1（根据角色更新对应字段）
        │
        ▼
    ┌───┴───┐
    ↓       ↓
 会话列表中  接收方在线
 显示未读角标 实时推送（但未读计数保留）
    ↓       ↓
用户点击会话 用户打开聊天页面
        │
        ▼
调用标记已读接口
PUT /system/chat/message/read/{sessionId}
        │
        ▼
    ┌───┴───┐
    ↓       ↓
标记所有消息已读  重置未读消息数
        │
        ▼
发送已读回执给发送方
        │
        ▼
发送方消息状态变为"已读 ✓"
```

## 十二、总结
### 12.1 核心业务规则
1. 商品必须审核通过后才能上架
2. 商品上架后可被购买，下单后自动变为"已预订"
3. 卖家可同意或拒绝订单
4. 买家可完成或取消交易中的订单
5. 订单取消后商品自动恢复"上架"状态
6. 取消/拒绝操作必须填写原因
7. 一个用户对同一商品只能收藏一次
8. 聊天消息通过 WebSocket 实时推送
9. 未读消息数在会话列表中实时更新

### 12.2 关键状态码
| 商品状态 | 订单状态 | 收藏状态 | 消息状态 |
| --- | --- | --- | --- |
| 0-待审核 | 0-待确认 | 存在-已收藏 | 0-未读 |
| 1-上架 | 1-交易中 | 不存在-未收藏 | 1-已读 |
| 2-已预订 | 2-已完成 | - | - |
| 3-已售出 | 3-已取消 | - | - |
| 4-已下架 | - | - | - |
